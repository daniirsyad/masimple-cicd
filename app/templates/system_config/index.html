Discord Integration

The Discord counterpart to Telegram above — same notifications and the same bot commands (/run, /status, /review, /build, /deploy, /update, /stop, /restart), connected via a persistent Gateway WebSocket rather than a webhook, so no public HTTPS endpoint is required. Create an Application + Bot at the Discord Developer Portal, copy its Bot Token and Application ID below, and invite the bot to a server you and each relevant user share (a bot can only DM someone it shares a server with). No privileged Discord intents are needed. Each user then finds their own numeric Discord User ID via Discord's Developer Mode ("Copy User ID") and sets it on their row on the Users page.

Off by default so adding a bot token alone doesn't start sending messages.

How to set up a remote Docker host (TLS)

Generates the commands to make a Linux (systemd) Docker host accept TLS connections on port 2376 and hand this app a client certificate. Run steps 1–3 as root on the Docker host.

{% call guide_step("docker-guide-1", "1. Create certificates (on the Docker host)") %}mkdir -p /etc/docker/certs && cd /etc/docker/certs # Certificate authority — keep ca-key.pem private: it can mint root access to this host openssl genrsa -out ca-key.pem 4096 openssl req -new -x509 -days 3650 -key ca-key.pem -sha256 -subj "/CN=docker-ca" -out ca.pem # Server certificate for __HOST__ openssl genrsa -out server-key.pem 4096 openssl req -new -key server-key.pem -subj "/CN=__HOST__" -out server.csr printf 'subjectAltName = __SAN__,IP:127.0.0.1\nextendedKeyUsage = serverAuth\n' > server.ext openssl x509 -req -days 3650 -sha256 -in server.csr -CA ca.pem -CAkey ca-key.pem -CAcreateserial -out server-cert.pem -extfile server.ext # Client certificate for this app openssl genrsa -out key.pem 4096 openssl req -new -key key.pem -subj "/CN=masimple-cicd" -out client.csr printf 'extendedKeyUsage = clientAuth\n' > client.ext openssl x509 -req -days 3650 -sha256 -in client.csr -CA ca.pem -CAkey ca-key.pem -CAcreateserial -out cert.pem -extfile client.ext chmod 600 ca-key.pem server-key.pem key.pem{% endcall %} {% call guide_step("docker-guide-2", "2. Make dockerd listen on TCP with TLS") %}# Merge by hand instead if /etc/docker/daemon.json already exists cat > /etc/docker/daemon.json <<'EOF' { "hosts": ["unix:///var/run/docker.sock", "tcp://0.0.0.0:2376"], "tls": true, "tlsverify": true, "tlscacert": "/etc/docker/certs/ca.pem", "tlscert": "/etc/docker/certs/server-cert.pem", "tlskey": "/etc/docker/certs/server-key.pem" } EOF # systemd's default "-H fd://" conflicts with "hosts" above mkdir -p /etc/systemd/system/docker.service.d printf '[Service]\nExecStart=\nExecStart=/usr/bin/dockerd\n' > /etc/systemd/system/docker.service.d/override.conf systemctl daemon-reload && systemctl restart docker ss -ltnp | grep 2376{% endcall %} {% call guide_step("docker-guide-3", "3. Open the firewall") %}# Ubuntu/Debian ufw allow 2376/tcp # RHEL/Rocky/Alma firewall-cmd --permanent --add-port=2376/tcp && firewall-cmd --reload{% endcall %} {% call guide_step("docker-guide-4", "4. Test from another machine") %}# Copy the client files over first; the paths below are relative to this folder mkdir -p ~/docker-tls && cd ~/docker-tls scp root@__HOST__:/etc/docker/certs/{ca,cert,key}.pem . docker --tlsverify --tlscacert=ca.pem --tlscert=cert.pem --tlskey=key.pem -H tcp://__HOST__:2376 version{% endcall %} {% call guide_step("docker-guide-5", "5. Give the certificates to this app's pod") %}kubectl -n __NS__ create secret generic docker-tls \ --from-file=ca.pem --from-file=cert.pem --from-file=key.pem # Then add to this app's Deployment (container "web"): # env: # - name: DOCKER_TLS_VERIFY # value: "1" # - name: DOCKER_CERT_PATH # value: /certs # volumeMounts: # - name: docker-tls # mountPath: /certs # readOnly: true # and under the pod spec: # volumes: # - name: docker-tls # secret: # secretName: docker-tls # Check the pod can reach the host before saving: kubectl -n __NS__ exec deploy/<app-deployment> -- curl -sv --max-time 5 telnet://__HOST__:2376{% endcall %}

6. Set Docker Host above to tcp://__HOST__:2376, click Test Connection, then Save.

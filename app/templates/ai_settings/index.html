How does the "Preview from Git" autofill work?

When you trigger a build and hit "Preview from Git", every commit since the last successful build on that branch is read and used to draft the four build fields:

  • Bump Type — always read straight from the commit messages, never AI. Highest priority: an explicit major:/minor:/patch: prefix — the developer just said what they meant, so this wins outright, even over a conflicting marker on the same line. Otherwise falls back to a Conventional Commits guess (a feat:/fix: prefix, a ! or BREAKING CHANGE marker, etc.). Defaults to "patch" if nothing looks conventional at all.
  • Object(s) and Change Type — first checked directly against the commit messages: if an existing Object or Change Type's name is spelled out literally in a commit message, that's used as-is, no AI involved. Only when nothing matches does an AI provider (configured below) get asked to guess from the commit messages instead — and it can only ever guess an existing Object/Change Type or propose a brand-new Object name; it never invents a new Change Type.
  • Description — always drafted by the AI provider as a short summary of the commit messages; there's no "spelled out in the commit" shortcut for this one.

Every field is just a pre-fill — still fully editable in the build-trigger modal, and nothing is saved until you actually submit the build. If no AI provider is configured or the call fails, Bump Type and any direct commit-message matches still come through; only the AI-only parts (Description, brand-new Object suggestions) are left blank.

Example

Naming an existing Object/Change Type directly in the commit message — and using a Conventional Commits prefix — lets three of the four fields resolve without the AI having to guess at all, which keeps its job (and token usage) down to just the Description: 

fix: resolve pagination bug in Checkout Flow (Bug Fix)
  • Bump Type → patch (the fix: prefix)
  • Object → Checkout Flow (spelled out directly)
  • Change Type → Bug Fix (spelled out directly)
  • Description → still drafted by the AI

Or state the Bump Type explicitly instead of relying on the Conventional Commits guess — useful when the change doesn't neatly fit feat/fix, or you just want to be unambiguous about it: 

minor: add discount code support to Checkout Flow (New Program)
  • Bump Type → minor (the explicit prefix — wins over any other signal)
  • Object → Checkout Flow (spelled out directly)
  • Change Type → New Program (spelled out directly)
  • Description → still drafted by the AI

A vaguer message leaves more for the AI to work out (and costs more tokens doing it): 

patched some stuff in the flow
  • Bump Type → patch (default guess — no recognized prefix)
  • Object and Change Type → the AI has to guess both from context
  • Description → still drafted by the AI
